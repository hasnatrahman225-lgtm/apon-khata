# আপন খাতা (Khatabook) — payment-free ledger app prototype

TallyKhata-এর মতো একটা ব্যবসায়িক খাতা/লেজার অ্যাপের কার্যকর প্রোটোটাইপ — কিন্তু:

- **কোনো পেমেন্ট/ওয়ালেট ফিচার নেই** (TallyPay QR-এর মতো কিছুই নেই)
- **লগইন শুধু ইমেইল/জিমেইল দিয়ে** — ফোন নম্বর দিয়ে নয়
- **ডেটা রিকভারি ইমেইলের সাথে বাঁধা** — যেকোনো ডিভাইস/ব্রাউজারে একই ইমেইল দিয়ে লগইন করলেই সব হিসাব ফিরে আসে

## কীভাবে কাজ করে (আর্কিটেকচার)

```
khatabook/
  backend/    ← Node.js + Express + SQLite API (একই ব্যাকএন্ড ওয়েব ও মোবাইল দুটোই ব্যবহার করবে)
  frontend/   ← React (Vite) ওয়েব অ্যাপ, ব্যাকএন্ডের API কল করে
```

**একটাই ব্যাকএন্ড, দুইটা ফ্রন্টএন্ড** — এটাই মূল ডিজাইন। ওয়েব অ্যাপ আর ভবিষ্যতে বানানো
অ্যান্ড্রয়েড অ্যাপ (React Native দিয়ে) দুটোই একই REST API-তে কল করবে, তাই ডেটা,
হিসাব-নিকাশের নিয়ম, এবং অ্যাকাউন্ট — সব জায়গায় এক থাকে।

### ডেটা রিকভারির মূল নিয়ম

`backend/src/db/index.js`-এ `users` টেবিলে **email** হলো একমাত্র স্থায়ী পরিচয় (primary
identity)। ইমেইল-পাসওয়ার্ড দিয়ে সাইন-আপ করুন বা Google দিয়ে — দুটোই একই ইমেইলে resolve
হয় এবং একই `user_id`-তে যায়। বাকি সব টেবিল (contacts, transactions, stock) সেই
`user_id`-এর সাথে বাঁধা। ফলে:

- ফোন হারালে/অ্যাপ ডিলিট হলে → নতুন ডিভাইসে একই ইমেইল দিয়ে লগইন করলেই আগের সব
  কাস্টমার, সাপ্লায়ার, লেনদেন ফিরে আসবে।
- একবার ইমেইল-পাসওয়ার্ড দিয়ে অ্যাকাউন্ট খুলে পরে Google দিয়ে লগইন করলেও (একই ইমেইল
  হলে) সেই একই ডেটা দেখাবে — দুটো আলাদা অ্যাকাউন্ট তৈরি হয় না।

এই নিয়ম পরীক্ষা করে দেখা হয়েছে: register → contact/transaction যোগ → logout → আবার
login → ডেটা অবিকৃত ফিরে এসেছে।

## চালু করবেন কীভাবে

### Backend

```bash
cd backend
cp .env.example .env      # JWT_SECRET বদলে দিন প্রোডাকশনে
npm install
npm start                 # http://localhost:4000
```

### Frontend (ওয়েব)

```bash
cd frontend
cp .env.example .env
npm install
npm run dev                # http://localhost:5173
```

## Google Sign-In চালু করা (ঐচ্ছিক)

এখন ইমেইল + পাসওয়ার্ড দিয়ে সম্পূর্ণ কাজ করে। আসল "জিমেইল দিয়ে লগইন" বাটন চালু
করতে:

1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials)-এ একটা
   **OAuth 2.0 Client ID (Web application)** তৈরি করুন। Authorized JavaScript origin-এ
   আপনার frontend-এর URL (যেমন `http://localhost:5173`, পরে প্রোডাকশন ডোমেইন) যোগ করুন।
2. `backend/.env`-এ `GOOGLE_CLIENT_ID=<আপনার client id>` বসান, সার্ভার রিস্টার্ট করুন।
3. `frontend/.env`-এ `VITE_GOOGLE_CLIENT_ID=<একই client id>` বসান, dev সার্ভার রিস্টার্ট
   করুন।

এটা না করা পর্যন্ত অ্যাপ শুধু ইমেইল/পাসওয়ার্ড দিয়ে চলবে — বাকি সব ফিচার (হিসাব, রিকভারি)
একই রকম কাজ করে, কারণ ব্যাকএন্ডে দুই লগইন পদ্ধতিই একই `users` টেবিলে মেলে।

## এখন যা যা আছে

- ইমেইল/পাসওয়ার্ড দিয়ে সাইন-আপ, লগইন (+ Google login-এর জন্য প্রস্তুত এন্ডপয়েন্ট)
- কাস্টমার ও সাপ্লায়ার তালিকা, প্রত্যেকের বাকি/জমার হিসাব
- "দিলাম" (বাকী) / "পেলাম" (জমা) — প্রতিটি এন্ট্রি টাইমস্ট্যাম্প ও নোটসহ
- ড্যাশবোর্ড: মোট পাওনা, মোট দেনা, সাম্প্রতিক লেনদেন
- স্টক/ইনভেন্টরি তালিকা (পরিমাণ, একক দাম)
- খাত অনুযায়ী রিপোর্ট + CSV ডাউনলোড
- **কোথাও কোনো পেমেন্ট গেটওয়ে, ওয়ালেট, বা QR পেমেন্ট নেই**

## এখনো যা বাকি (পরবর্তী ধাপ)

- **অ্যান্ড্রয়েড অ্যাপ**: React Native (বা Expo) দিয়ে বানিয়ে এই একই `backend/` API
  কল করবে — স্ক্রিন ও ব্যবসায়িক নিয়ম (balance হিসাব ইত্যাদি) backend-এই আছে, তাই মোবাইল
  অ্যাপ মূলত UI + এই API কল।
- SMS/WhatsApp দিয়ে বাকির রিমাইন্ডার পাঠানো (এখন শুধু ভেতরের রিপোর্ট আছে)
- পাসওয়ার্ড ভুলে গেলে রিসেট-লিংক (ইমেইলে পাঠানোর জন্য একটা মেইল সার্ভিস, যেমন
  SendGrid/SES যোগ করা লাগবে)
- প্রোডাকশনে SQLite-এর বদলে PostgreSQL-এ যাওয়া (একই স্কিমা, বেশি ব্যবহারকারীর জন্য)
- ডেটা এক্সপোর্ট/ব্যাকআপ (JSON) — recovery ইতিমধ্যেই ইমেইল-লগইন দিয়ে কাজ করে, এটা
  বাড়তি সুরক্ষা হিসেবে
